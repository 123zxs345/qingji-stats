# 发布到 GitHub Pages

本地仓库已经准备好并完成首次提交，工作流也已就位。剩下四步需要已登录的 GitHub 账号操作。

## 1. 新建空仓库

打开 <https://github.com/new>：

- **Repository name**：`qingji-stats`（可改名，改完记得同步第 4 步的工作流默认地址）
- **Visibility**：`Public`（免费账号的 Pages 只对公开仓库开放）
- **不要**勾选 Add a README / .gitignore / license —— 保持空仓库，否则推送会被拒绝

## 2. 推送本地提交

在项目里执行（Windows PowerShell）：

```powershell
cd E:\微信小程序\sites\wechat-stats-demo
git remote add origin https://github.com/123zxs345/qingji-stats.git
git push -u origin main
```

第一次推送会弹出 GitHub 登录窗口，登录后即可完成。如果仓库名不是 `qingji-stats`，把上面的地址换成实际地址。

## 3. 配置数据库变量（可选，但云端同步需要）

仓库页面 → **Settings** → **Secrets and variables** → **Actions** → **Variables** 标签页 → **New repository variable**，添加两个：

| Name | Value |
| --- | --- |
| `TINYWEBDB_USER` | `zqhscut` |
| `TINYWEBDB_KEY` | TinyWebDB 账号的 API 密钥（不是登录密码） |

不配置也能正常发布，网页照常可用，只是只保存到本机、不同步云端。工作流已经预留这两个变量的读取位置。

## 4. 打开 Pages

仓库页面 → **Settings** → **Pages** → **Build and deployment** → **Source** 选择 **GitHub Actions**。

推送完成后工作流会自动运行（也可以在 **Actions** 标签页手动 Run workflow）。等它变绿，公开地址是：

```text
https://123zxs345.github.io/qingji-stats/
```

如果仓库名不是 `qingji-stats`，地址相应变化；工作流里的站点地址取自 GitHub 提供的实际地址，不需要手工改，但 `scripts/build.mjs` 里的默认值用于本地导出，建议一并同步。

## 发布后自查

1. 打开公开地址，确认标题是「轻记 · 数字统计」。
2. 切到「次数统计」，输入 `1 2 1 50`，保存后应当显示 `1（2）、2（1）、50（1）`，合计 4。
3. 切回「数量累加」，输入 `1(100) 2(50)` 和 `1(88) 2(896)`，应当显示 `1（188）、2（946）`，合计 1134。
4. 右上角同步文字：配置了变量应当变成「云端已同步」；没配置则一直是「已保存到本机」，这属于预期。
5. 刷新页面，记录应当还在。
6. 手机上打开，确认没有横向滚动条、按钮都点得到。
